# DB ダンジョン

データベースの内部構造をダンジョンとして降りていく、ブラウザの RPG です。
SQL がパーサー → 意味解析 → オプティマイザ → 実行 → ストレージと処理される順番を、そのまま階層にしています。
遊んでいるうちに「DB の中で SQL がどう扱われているか」がわかることを目指しています。

いま遊べるのは **B1 パーサー階の Lv1〜Lv3**（`SELECT *`・列の指定・`WHERE` の条件）です（試作）。

## 遊び方

- 敵は「お題」を出してきます。敵の種類で、やることが変わります
  - **書く**：文章のお題（例：users 表の中身を全部見せろ）を読んで SQL を書く
  - **木を読む**（ゴーレム）：構文木を見せられて、その木になる SQL を書く
  - **直す**（ミミック）：1 か所壊れた呪文を書き直して唱え返す
- お題に合う SQL を **呪文として自分で打って** 唱えます（Tab で補完、Ctrl+Enter で唱える）
- 本物の SQL パーサー（[node-sql-parser](https://github.com/taozhi8833998/node-sql-parser)、SQLite 方言）が呪文を構文木にします
- お題が求める構文木の部品と照合し、1 回の呪文で全部の部品がそろえばお題を 1 つくずせます（敵の HP＝お題の数）
- 敵のターンには「呪われた呪文」（1 か所壊れた SQL）が飛んできます。おかしい単語を当てれば防御成功です。
  答え合わせでは、元の呪文と、本物のパーサーが実際に読めなくなった場所を見せます。
  たとえば `SELEC * FROM users` の間違いは `SELEC` ですが、パーサーが困るのはその次の `*` です。人が見た間違いとパーサーが読めなくなる場所はずれることがある、というのがこの階の発見です
- 文法を間違えると、パーサーが実際に読めなくなった位置で呪文が途切れ、反動を受けます
- 部品が合わなかったときは、どこが惜しいかを教えてくれます。たとえば `WHERE 20 <= age` は `WHERE age >= 20` と意味は同じですが、構文木では左右が入れ替わった別の木なので外れます。パーサーは意味を知らず、形だけを見るからです（数の `20` と文字列の `'20'`、`'bob'` と `"bob"` も別物です）
- 画面下の「解析の書」で、字句解析・構文木・照合の結果を見返せます

## 大事にしていること

**本物の DB とずれないこと。** たとえば 1 面はパーサーの階なので、勝ち負けは「構文木の形」だけで決めます。
存在しない表名もパーサーは通します（表があるかを確かめるのは次の意味解析の仕事です）。ゲームでもそのとおりに振る舞います。
レベルを上げても攻撃力は増えません。強くなる＝書ける文法が増える、です。

```sh
npm run build    # 型チェック＋ビルド
```
